# 主控提示词辅助

派发承接本域已确定的讨论结论。若研究目标或关键取舍尚未清楚，主控可使用[共同设计技能](../camp-discuss/SKILL.md)先讨论；已经明确的任务直接派发。只传与任务有关的决定、理由和证据入口，不把用户尚未接受的建议写成要求。

任务写成同事能够直接开展工作的说明：
- 你是哪个域哪个岗位；本次只做什么，为什么做。
- 已知结论、必要材料绝对路径；不要求重新扫描整个项目。
- 实验目录、配对/接收岗位；规划交 Markdown 原文，执行交真实结果，分析交证据结论。
- 完成标准、允许写入范围、实测模型及调用次数（框架验证0）。区分对话型号与供应商模型。
- 明确下一步接收者、异常报哪个主控；不加大段ID、SHA、协议封套、重复检查或例行审批。
先检查提示词是否把完整实验拆碎、要求下游重复搬材料、引用旧流程或遗漏必要输入。具体任务自然语言即可，不必固定JSON模板。只有主控实际安排新实验，岗位正常交接不等于新增实验授权。

## 多批研究增量

任务注明所属批次、初始/必要后续/补充性质、本项供应商调用上限和分析归属；只交付当前批。规划完成直接交同编号试验场，不增加主控例行审批。岗位只更新自身材料，不修改主控夜间状态；回报包含实际调用、结果不明占用、结果路径和是否空闲。说明本批补充截止条件，不把后续批次候选当成当前授权。主控发送前记录分配额度，发送后保留回执，明确入队/未发送/不明，防止重复派发与重复占用预算。

## 最小上下文与交接

首次读取项目必要 README、[共用规则](../../basecamp/WORKFLOW.md)与本技能，之后只读任务增量。真实地址见项目 .codex-basecamp/roles.json。通过 [唯一收发入口](../../basecamp/README.md) 交接，正文简短并提供绝对路径；忙时排队，不插话、不自行创建对话。消息 accepted 仅表示入队；发送不明不重复发送。只执行本项目当前授权任务；示例、历史记录与岗位初始化不授权研究调用。对话模型不等于实测视觉模型。不要从历史框架恢复 SHA 封套、预登记、多层合同、强制脚本或全量经验加载。
