# Codex Basecamp · 多对话协作基地车

公开模板仓库：[CPZIOO4/codex-basecamp](https://github.com/CPZIOO4/codex-basecamp)。固定首版：`v1.0.0`。

把这个仓库放进Codex，它可以按 [START.md](START.md) 将长期多对话协作体系展开到新项目或已有项目。安装副本自包含，源仓库移走后仍能使用，也能再展开另一个项目。

在Codex打开本仓库后说：

> 请按START.md把基地车展开到当前项目，创建长期协作岗位，所有岗位共享当前目录。项目目标是：……。

也可以先展开到其他项目：

```text
python basecamp.py init --target "目标项目目录"
```

接下来由目标项目的Codex主控读取安装后的START，检查本机能力、登记当前主控并创建其他岗位。无需复制旧项目的任务、对话地址或认证。

## 保留的协作方式

主控安排完整任务，规划直接交配套试验，试验交指定分析，分析回报主控；整理直属主控。长期岗位空闲时结束本轮并保留对话，后续消息原生排队，不打断忙碌岗位。

- 默认每域13岗：1主控、4规划、4试验、3分析、1整理；`--layout compact`为每类1岗，共5岗。当前对话登记为主控后，只需创建其余岗位。
- `--domain 产品 --domain 数据`可展开多个独立业务域；材料、决定与调用额度各自管理。
- 自动安装项目AGENTS入口、十项职责技能、工作流和运行器；保留已有README和业务文件，冲突不覆盖，同版重复执行不重复安装或建岗。
- 记录入队、激活与创建结果；超时不明不会自动重发或重复创建，可核对真实地址后接续。
- 默认继承模型和权限。明确选择模型时可配置覆盖，期望与实际观察分开；不擅自修改全局设置。

## 运行条件与验证

文件展开要求Python>=3.11。实际自动岗位运行还需要兼容的Codex桌面、CLI和当前用户登录；本版真实检查平台为Windows，CLI 0.154.0。`doctor --live`核对当前安装的桌面工具与排队接口；其他系统的文件展开不等于桌面自动化已经支持。

39项离线测试中38项通过、1项符号链接测试因本机权限跳过；真实只读能力检查通过；未登录从公开仓库克隆、展开44份文件、重复安装零变化及安装副本能力检查均通过。没有在本次创建或执行一组真实业务岗位，不把模拟整链或接口存在称为真实多岗位验收。详情见 [验证记录](docs/validation.md)。
